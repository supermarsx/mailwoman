# Product security information

The **About Mailwoman** tab of **Compliance**, and **Settings > About** in the mail app, show the facts the server was built with, a declared support end date, links for reporting a vulnerability, and downloadable software inventories. Nothing is fetched from another service when the tab opens. The information supports your own vulnerability handling; it does not establish conformity with any regulation, and the tab says so.

![The About Mailwoman tab of Compliance with the build facts (version, revision and target masked), the software inventory downloads and the links for reporting a vulnerability.](/screenshots/admin-privacy/product-security.webp){.mw-shot}

## What the tab shows

- **Version**, **Source revision**, **Release tag**, **Build target** and **Declared support end date**. The support end date is **Not declared** unless the server was built with `MW_PRODUCT_SUPPORT_UNTIL` set to a date (`YYYY-MM-DD`). A source revision identifies the commit the build came from; it is not a signature.
- **Software bill of materials**: the number of components and the SHA-256 of `Cargo.lock` and `pnpm-lock.yaml`.
- **Download backend inventory**: a CycloneDX 1.6 inventory generated at build time from `Cargo.lock`. It lists the whole workspace lock, including development and platform-specific packages, so it is not an exact list of what is linked into this binary.
- **Download frontend inventory**: the npm packages bundled into the web client, generated by the web build.
- **Download security policy**: the project's `SECURITY.md` as built into the server.
- **Report a vulnerability privately**, **Security advisories** and **Releases and updates**: links to the project's repository, fixed at build time.

Native libraries, container images, plugins and vendored files are not covered by either inventory.

## Public addresses

The same facts are served without sign-in at `/api/product-security`, the backend inventory at `/api/product-security/sbom` and the policy at `/api/product-security/policy`. Anyone who can reach the server can read the exact version, source revision and build target there.

## Build variables

| Variable | Effect |
| --- | --- |
| `MW_PRODUCT_SUPPORT_UNTIL` | Declares the support end date shown on the tab |
| `MW_BUILD_REVISION` | The source commit, for builds from an archive without Git history (also a Docker build argument) |
| `SOURCE_DATE_EPOCH` | The build time recorded in the facts |
