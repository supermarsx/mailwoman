# Declared native metadata guard inputs

Source candidate only; runtime/type/query-count gates are pending. This is not a
zero-SQL path or a throughput claim. It supports the actual DEFAULT36 single
Email/get with1..50 explicit IDs. Mixed calls, createdIds, result references,
body/raw requests and other properties are not declared. Cookie SQLite native
accounts with a positive telemetry throttle are the first eligible authority
backend; PostgreSQL and unknown/ineligible/cold sources retain original readers.

The shared JSON declaration is optional and is not authority. Both browser
request builders use the already parsed request object, with no generic
transport JSON parse. Native bearer and linked paths are not marked. WS permits
exactly the same header and its in-memory request Body size can establish the
bounded header-only hint. No earlier guard polls/parses the body. The original
feature guard body boundary validates the exact real method/arguments/DEFAULT36;
the handler binds the unchanged bytes again. The feature reader passes its
already parsed Value from those same bytes, avoiding a third successful JSON
parse; the handler parses only if that earlier byte binding is absent/changed. Even cold declarations cannot
execute a forged mutation/mixed/createdIds body.

The existing authenticated publication worker optionally constructs global
configuration DATA once per Store/generation/schema/Policy+Routing+Protection
vector. A bounded weak shared map participates in the existing128MiB logical
retention/component budget; it is not a process/in-flight/RSS limit. No allow,
Session or plaintext credential is cached. No legacy settings revision is
fabricated or borrowed to certify the DATA. Ordinary errors and global parser
semantics remain at each original guard point.

An original guard first requests one fresh source frame before consuming these
inputs. The task-local request scope compares current primary owner, parent,
source epochs and exact schema. Reused configuration points: protocol, admin
probe, request-protection configuration, trust policy, empty-domain rate knobs,
inbound configuration (only when the already locked runtime is identical),
client access, maintenance, global session-watch configuration and geography.
DNS answer freshness/refresh, trust hydration, protection/probe/quota SQL,
watch binding/tombstone/device/user-preference reads and writes, clocks and
country decisions remain live in their original locations. Source-ban reads
remain original. This is a coherent earlier input boundary plus a mandatory
final fence, not a claim of fresh DB reads at every original guard instant.

Every consumed context requires the real validated body and the same source/
schema vector in the LAST native joint auth+mail-data observation. Unsupported
native preparation cannot fall through to the ordinary handler; source changes
cannot use the inner auth-only restart (which does not rerun outer guards).
Failure-only original authentication can preserve expiry cleanup/error status,
but never authorizes application dispatch. Unconsumed routes keep old fallback.

A fresh observation can discover a last_seen telemetry deadline crossed while
queued. Only that due case performs an opaque Store/generation/epoch/actor CAS
on last_seen and repeats the SAME joint query once. Normal hits do not UPDATE.
Store checks source-created/activity equality and current idle/absolute deadlines
again under the write transaction; SQL checks database current time as well.
Activity, deadlines, credentials and missing sessions are never renewed/recreated.
Zero affected rows may mean a concurrent legitimate touch; only the fresh final
frame can establish same actor/current clocks/no-longer-due. No successful
source await follows the final query. Durable policy/expiry/process checks and
original quota predicates remain unchanged.

Auth input hint, feature presence/post-body revision refresh and native initial/
final observations remain. Worker SQL is separately accounted. The proposed
whole-router count oracle reports actual counts, not an inferred two-read HTTP.
No async outbox lag or TTL proves independent-writer freshness.
